# Fraud Detection Pipeline (Supervised Learning, Class Imbalance, SMOTE)

DecodeLabs Data Science Internship, Project 2 (Batch 2026).

An end-to-end, leak-free fraud detection workflow on a highly imbalanced
credit-card dataset (`creditcard.csv`: Time, V1-V28, Amount, Class).

## What is inside
- `Project2_Fraud_Detection.ipynb`: the full notebook (14 sections, explanations between code cells)
- `REPORT.md`: management report, auto-generated by the notebook from the real results
- `model_comparison.csv`, `figures/`: outputs written by the notebook
- `requirements_project2.txt`

## Approach
| Step | What was done |
|---|---|
| Data understanding / cleaning | Schema checks, duplicate removal, median imputer kept in the pipeline for safety |
| EDA | Class imbalance, amount and time patterns, correlation with the label, outlier analysis |
| Feature engineering | 7 stateless features (hour, night flag, log amount, zero/round amount flags, PCA-space norm and max) |
| Split | Stratified train / validation / test; test set used once at the end |
| Imbalance | SMOTE inside an `imblearn` Pipeline, training folds only, plus an experiment showing the inflated scores caused by SMOTE-before-split |
| Models | Logistic Regression (scaled) and Random Forest |
| Tuning | GridSearchCV (LR) and RandomizedSearchCV (RF), scored on PR-AUC, SMOTE ratio tuned as a hyper-parameter |
| Evaluation | Precision, Recall, F1, ROC-AUC, PR-AUC, confusion matrices, bootstrap confidence intervals; accuracy is deliberately not used |
| Business view | Threshold chosen on validation data, cost table with adjustable assumptions, feature importance (impurity, permutation, coefficients) |

## Results
Full run on Kaggle (CPU), dataset: ULB *Credit Card Fraud Detection* (284,807 transactions, 492 frauds = 0.173%;
473 frauds / 283,726 rows after removing 1,081 duplicates). Metrics below are from a **one-time evaluation on an untouched test set**
(fraud rate 0.167%), at a decision threshold chosen on a separate validation set.

| Model | Precision | Recall | F1 | ROC-AUC | PR-AUC | Train time | Scoring (ms / 1k rows) |
|---|---|---|---|---|---|---|---|
| **Random Forest (selected)** | 0.932 | 0.726 | 0.817 | 0.957 | 0.813 | ~122 s | ~7.6 |
| Logistic Regression | 0.871 | 0.642 | 0.739 | 0.955 | 0.705 | ~2.5 s | ~0.7 |

Selection was made on **validation** PR-AUC (RF 0.875 vs LR 0.818), not on the test set.

**Key findings**
- Accuracy is meaningless here: predicting "legitimate" for everything scores 99.83% accuracy with 0% recall.
- **Leakage experiment:** applying SMOTE *before* the split inflated PR-AUC from 0.706 (correct) to 0.991 and precision from 0.047 to 0.973. The honest number is the lower one.
- Top features by permutation importance: V12, V14, V3, `v_norm` (an engineered feature), V4.
- Random Forest and Logistic Regression are nearly tied on ROC-AUC (0.957 vs 0.955); the gap shows up on PR-AUC, the metric that matters under extreme imbalance.
- Test metrics rest on only ~95 fraud cases, so they are noisy (the notebook reports bootstrap confidence intervals).

Full narrative: `REPORT.md`. Charts: `figures/` (12 images).

## How to run
**Kaggle (easiest, dataset is one click):** New Notebook -> File -> Import notebook -> upload the `.ipynb`
-> Add Input -> search "Credit Card Fraud Detection" -> Run All.

**Colab:** upload `creditcard.csv` to the session files, then Runtime -> Run all.

**Local:** `pip install -r requirements_project2.txt`, put `creditcard.csv` beside the notebook, run it.
Set `QUICK=1` in the environment for a fast smoke test.

## Limitations
Few fraud examples (noisy test metrics), anonymised PCA features, random rather than time-based split,
simplified cost model, tuning on a training subset for compute reasons.
